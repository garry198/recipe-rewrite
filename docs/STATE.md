# Текущее состояние (baseline = rewr-transl_22, CHECKS c9)

## Что работает
- Рерайт EN: промпт v3_5 + детерминированная пред/постобработка (масштабирование к 4 порциям при >8, склейка строк,
  бренды, ссылки на рецепты, безопасные температуры 165/160°F, проверки prep/form/style, строгий режим + автоисправление).
- Перевод FR: плейсхолдеры `[[Q#]]/[[T#]]`, конвертация единиц, термостат духовки, валидация перевода.
- Кэш по хэшу (промпт, модель, порции, режим, локаль, версии UNITS/SCALE/CHECKS), учёт токенов `api_usage.csv`.
- ~50 регрессионных тестов, без БД и API.

## Известные проблемы
1. Расчёт стоимости не сходится с биллингом Google (≈$0.0022/рецепт в логе). Нужны токены и сумма из консоли Google.
2. Перевод только FR; немецкого нет. Локаль зашита в код (словарь, `OVEN_MAP`, `CUP_GRAMS`), не в данных.
3. Кэш — JSON с ключом по хэшу промпта: любая правка текста промпта обнуляет кэш.

## Дорожная карта (порядок)
- r01 — инвентаризация БД и контрактов (без кода) (**слита** в `main`)
- r02 — промпт v3_5 как дефолт (дубликат v3_6 удалён), порог масштабирования 8, тесты (**слита** в `main`)
- r03 — дизайн-документ «локали как данные» (`locales/fr_FR.yaml`, `de_DE.yaml`): словарь, меры, духовка, форматы записи
- r04 — реализация слоя локалей, FR переносится без изменения результата (регресс по логам)
- r05 — DE: промпт, меры (г/мл, EL/TL, Prise), духовка (Ober-/Unterhitze, Umluft), тесты
- r06 — кэш: SQLite с `policy-version` (идея из ветки Book Pipeline, `rescale_cache.py`)
- r07 — таксономия единиц в YAML (идея из `units.yaml`/`measures.py`), строгие проверки дробных штучных позиций

Источник идей для r06–r07: файлы ветки Book Pipeline (читать как референс, не копировать целиком: там US-ориентированные меры).
