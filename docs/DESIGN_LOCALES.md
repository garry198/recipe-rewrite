# Дизайн-документ: локали как данные (`locales/<locale>.yaml`)

Цель: вынести данные перевода и локальных мер из кода `rewr-transl.py` в декларативные YAML-файлы (`locales/fr_FR.yaml`, затем `locales/de_DE.yaml`), сохранив побайтовую идентичность вывода для FR.

## 1. Инвентаризация текущего кода (r03.1)

|---|---|---|---|
| Ложки (`"c. à c."`, `"c. à s."`) | `_convert_measure` (623–626) | данные | да |
| Десятичная запятая (`.` → `,`) | `_fr` (584–585), вызов в `_fmt_g`, `_fmt_vol`, `_fmt_cm`, `_convert_measure` (624, 626, 637) | данные | да |
| Тире-диапазон (`"–"`) | `_rj` (610–615), `_convert_measure` (624, 626), `_convert_temp` (668) | данные + логика склейки | да (символ), нет (логика `_rj`) |

| Удаление блока нутриентов (`"Valeurs nutritionnelles"`) | `strip_nutrition_block` (700–704) | данные (ключевые фразы) + логика | да (фраза на языке локали) |

| Параметры локали, промпт, БД и цена | `TARGET_LANG` (89, 1273 в промпте батча), `TARGET_LOCALE` (90, 910 в `run_hash`, 1010 в БД), `TARGET_MARKET` (91, 1010 в БД), `TARGET_CURRENCY` (92, 1011 в БД), `PROMPT_FILE_TRANSLATE` (95), `USD_TO_TARGET_RATE` (только `.env.example:39`, в коде не читается) | данные / конфиг | да |

## 2. Схема `locales/<locale>.yaml` (r03.2)

Формат YAML выбран за читаемость таблиц/списков и сохранение порядка элементов (`cup_grams`).

```yaml
meta:
  locale: fr_FR              # значение для recipe_rewrite.locale и TARGET_LOCALE
  lang: fr                   # для промпта батча ("Target Language: FR")
  market: fr                 # значение для recipe_rewrite.market
  currency: EUR              # значение для recipe_rewrite.currency
  usd_rate: 0.92             # default курса USD -> currency (переопределяется env при необходимости)
  prompt_file: prompts/desserts_translate_prompt_fr_v4.txt

number_format:
  decimal_sep: ","           # разделитель дробной части (или ".")
  range_sep: "–"             # разделитель диапазонов

spoons:
  tsp: "c. à c."
  tbsp: "c. à s."

units:
  weight:
    g_step: 5                # округление граммов, начиная с g_step_min
    g_step_min: 25
    kg_from_g: 1000
    kg_step: 0.05
    g_suffix: "g"
    kg_suffix: "kg"
  volume:
    ml_step: 5
    ml_step_below: 100
    use_cl: true             # для FR = true (100..999 мл -> cl); для DE уточнить
    cl_below_ml: 1000
    l_from_ml: 1000
    ml_suffix: "ml"
    cl_suffix: "cl"
    l_suffix: "l"
  length:
    mm_below_cm: 1
    half_cm_below: 5
    mm_suffix: "mm"
    cm_suffix: "cm"

# Порядок записей ЗНАЧИМ: используется первое совпадение подстроки в хвосте ингредиента.
cup_grams:
  - ["cilantro", 16]
  - ["parsley", 15]
  # ... все 50 записей в точном текущем порядке ...
  - ["cheese", 110]

oven:
  tolerance_f: 12
  template: "{c}°C (Th. {th})"   # при отсутствии th используется "{c}°C"
  entries:
    225: { c: 110, th: "3-4" }
    250: { c: 120, th: "4" }
    # ... до 500°F

# Слова в хвосте после oz/ounce, при которых oz трактуется как объём (fl oz -> ml/cl)
containers:
  - "ramekins?"
  - "glass(?:es)?"
  - "mugs?"
  - "jars?"
  - "cups?"

nutrition_headers:
  - "Valeurs nutritionnelles"
  - "Nutritional values"
  - "Calories\\s*:"
```

### Что остаётся в коде и почему
- **Регулярки и парсинг источника** (`_UNI_FRAC`, `TOKEN_RE`, `TEMP_RE`, `_LEFTOVER_RE`, `_NUM_RE`, `_to_float`): входной текст всегда на EN/US, правила разбора не зависят от целевой локали.
- **Математика и склейка** (`_rj`, шаги округления, коэффициенты пересчёта `29.57`, `240`, `946`, `28.35`, `453.59`, `2.54`): формулы едины, меняются только параметры из YAML.
- **Стэш плейсхолдеров и валидация** (`_stash`, `protect_units`, `restore_units`, `validate_translation`, `final_check`): механика защиты `[[Q#]]`/`[[T#]]` и поиска остатков английских слов не зависит от целевого языка.

### Загрузка и валидация
- Загрузка происходит **при старте скрипта** (`load_locale(TARGET_LOCALE)`), до `generate_run_hash()` и подключения к БД.
- Схема валидируется строгой Pydantic-моделью (`LocaleConfig` с `extra="forbid"`): при отсутствии файла `locales/<locale>.yaml`, неверном типе поля или **неизвестном ключе** скрипт падает сразу с понятным сообщением (имя файла и путь к полю).

## 3. Перенос FR без изменения результата (подготовка r04, r03.3)

- **Golden-тест**: собрать корпус не менее ~200 реальных строк из логов/CSV владельца (в репозитории `logs/` сейчас пуст — только `.gitkeep`), `tests/test_regressions.py` и краевых случаев: диапазоны (`1-2 cups`, `350-375°F`), размеры с `x` (`9x13 inch`), `quart` (`5- to 6-quart`), `ramekin` (`4 oz ramekins`), температуры с дублированием в Цельсиях (`350°F (175°C)`), порядок `CUP_GRAMS` (`almond flour`, `cream cheese` vs `cheese`), юникод-дроби. Прогнать `protect_units` + `restore_units` на старом коде и на `locales/fr_FR.yaml` и требовать **побайтовое совпадение**.
- **`UNITS_VERSION` и `run_hash`**: в `r04` значение `UNITS_VERSION` остаётся `"u2"`, сигнатура и состав `generate_run_hash()` не меняются — кэш не сбрасывается. Нельзя добавлять в `run_hash` содержимое YAML, путь к файлу или новые поля без осознанного бампа `UNITS_VERSION`.
- **Совместимость `tests/test_regressions.py`**: тесты вырезают код по маркерам `# ================= UNITS_FR` ... `# ================= СХЕМЫ ДАННЫХ` и выполняются без БД, API и `.env`. В `r04` маркеры сохраняются, а загрузка дефолтной локали `fr_FR` из `locales/fr_FR.yaml` должна работать автономно от `BASE_DIR` без чтения `.env` и без подключения к БД/API.

## 4. Заготовка `de_DE` — только кандидаты (r03.4)

- **Ложки и щепотка**: `EL` (Esslöffel, tbsp), `TL` (Teelöffel, tsp); `Prise` для `pinch` (сейчас `pinch` не входит в `TOKEN_RE`).
- **Единицы и числа**: `g`, `kg`, `ml`, `l`, `mm`, `cm`; десятичная запятая `,`, тире-диапазон `–`. Использование `cl` (сантилитров) в немецких рецептах нетипично — вынесено в вопросы.
- **Духовка**: `°C`, возможные режимы «Ober-/Unterhitze» (верх/низ) и «Umluft» (конвекция, обычно `-20 °C`). В схеме `oven` можно поддержать через `template` (например, `"{c}°C Ober-/Unterhitze ({c_conv}°C Umluft)"` или только `"{c}°C"`), точный формат — вопрос владельцу.
- **`cup_grams`**: плотности и названия ингредиентов не придумываются. Поскольку `protect_units` матчит EN-исходник до перевода, нужно проверить, достаточно ли текущих ~50 EN-ключей `CUP_GRAMS` (и нужно ли в промпте запрещать «Tasse»/«Becher» или переводить оставшиеся).

## 5. Влияние на соседей (`docs/CONTRACTS.md`, r03.5)

- При добавлении `de_DE` в `docs/CONTRACTS.md` нужно зафиксировать новые значения: `market = 'de'`, `locale = 'de_DE'`, `currency = 'EUR'` (в принятом регистре).
- **Влияние на `cost-nutrients` и `Book Pipeline`**: оба потребителя читают `recipe_rewrite` и фильтруют по `market`/`locale` (с учётом правила `LOWER(market)` из `r01.5`). Добавление строк `de`/`de_DE` не затронет текущие выборки для `US`/`fr`, но `cost-nutrients` потребуется поддержка расчёта цен для рынка DE в EUR, а `Book Pipeline` — поддержка локали `de_DE` в шаблонах книги.

## Открытые вопросы владельцу

1. Нужен ли `cl` (сантилитры) для `de_DE` или выводить только `ml` / `l` (`use_cl: false`)?
2. Какой формат духовки по умолчанию использовать для `de_DE` (`"180°C"`, `"180°C Ober-/Unterhitze"` или с указанием `"Umluft"` минус 20°C)?
3. Как обрабатывать `Tasse` / `Becher` (если `cup` не попал в `CUP_GRAMS`) и нужно ли добавлять `pinch` → `Prise` в конвертер?
4. Нужна ли десятичная запятая в диапазонах и дробях для `de_DE` так же, как в `fr_FR` (например, `1,5–2 EL`)?
5. Какая валюта и какой курс по умолчанию (`usd_rate`) задавать для `de_DE` (`EUR`, `0.92`)?
6. Подтвердить значения для БД `recipe_rewrite`: `market = 'de'`, `locale = 'de_DE'` (в нижнем регистре `market`, как `'fr'`).
7. Какое имя файла системного промпта планировать для немецкого перевода (например, `prompts/desserts_translate_prompt_de_v1.txt`)?
