# Эталонный набор `recipes3.id` для проверки до/после

Используется при изменении логики масштабирования, проверок (`checks.py`) или системного промпта.

## Состав набора (14 рецептов)

| `recipes3.id` | Проверяемое поведение |
|---:|---|
| `4127` | 12 порций, дробные яйца → выбор 6 порций (`choose_target_servings`) |
| `4801` | яйцо в ложки, 12 → 8 (оба кандидата дробные, возвращается `base`) |
| `4215` | масштабирование 16 → 8 |
| `4277` | масштабирование 60 → 32 |
| `4423` | ссылка на другой рецепт — должен пропускаться (`SKIP_RECIPE_REFS=1`) |
| `4436` | ссылка на другой рецепт — должен пропускаться (`SKIP_RECIPE_REFS=1`) |
| `3562` | опечатки источника |
| `3972` | желтки, `divided` |
| `2260` | 12 → 8, рассол |
| `1243` | 24 → 16, дробные меры |
| `4411` | масштабирование 10 → 4 |
| `4414` | конвертация г/кг в `lb` |
| `3801` | сохранение `dish_name_variant` при `ADAPT_FORCE=1` (`FORCE_KEEP_DISH_NAME=1`) |
| `3813` | количество только в скобках → отключение масштабирования (`RESCALE_SKIP_PAREN_QTY=1`) |

Строка для `.env`:
```ini
ADAPT_IDS=4127,4801,4215,4277,4423,4436,3562,3972,2260,1243,4411,4414,3801,3813
```

## Как запускать эталонный прогон (только владелец)

> Воркер API не запускает. Фактический прогон выполняет владелец.

1. Перед изменениями (на `main`) и после изменений (на ветке `worker/rNN`) задать в `.env`:
   ```ini
   APP_MODE=adapt
   ADAPT_FORCE=1
   ADAPT_LIMIT=20
   ADAPT_IDS=4127,4801,4215,4277,4423,4436,3562,3972,2260,1243,4411,4414,3801,3813
   DRY_RUN=1
   ```
2. Запустить `python rewr-transl.py 2>&1 | Out-File logs\ref_run.log -Encoding utf8`.
3. Сравнить результаты до и после:
   - `logs/force_report_<ts>.md` и `.csv` (порции, unified diff ингредиентов, список пропущенных);
   - `logs/rewrite_update_log.csv` (сохранить копию «до» перед вторым прогоном и сравнить колонки `Rewritten Servings`, `Rewritten Ingredients`, `Rewritten Instructions`, `Status`).

## Что пишет воркер в `worker_notes.md`
В разделе **«Проверка на эталоне (было/стало)»** воркер описывает ожидаемые различия на основе кода и юнит-тестов (или указывает «не применимо» с причиной, если код рерайта/проверок не менялся), а фактический прогон с API оставляет владельцу.
